# Multi-Agent Blackjack · Expectimax 실험실

대학교 인공지능입문 팀 프로젝트용 Python + HTML/CSS/JavaScript 시뮬레이터입니다. AI 플레이어 A/B와 규칙 기반 딜러가 5라운드를 진행합니다. 사용자는 전략을 대신 선택하지 않고 이벤트 진행과 분석을 제어합니다.

**턴 진행 기본 규칙:** 최초 카드 배분이 끝나면 첫 플레이어가 Stand/Bust가 될 때까지 계속 Hit/Stand를 판단합니다. 이어 두 번째 플레이어도 자신의 턴을 끝까지 진행하고, 두 플레이어가 모두 종료된 뒤 딜러가 진행합니다. Hit마다 A/B/딜러가 번갈아 행동하지 않습니다. `TURN_START`와 `TURN_END` 이벤트, 현재 턴 강조, 진행 표시줄로 차례를 확인할 수 있습니다. 첫 행동자 선정 규칙(첫 라운드 무작위, 이후 자본 우위/동률 역순)은 유지합니다.

## 실행

Python 3.10 이상과 최신 브라우저가 필요합니다. 외부 pip/npm 패키지는 사용하지 않습니다. 실제 검증 환경은 Windows / Python 3.14.7입니다. 다른 Python 버전은 별도로 실행 검증하지 않았습니다.

프로젝트 폴더에서:

```powershell
python agent.py
# 같은 프로그램의 다른 진입점
python main.py
```

실행하면 Python의 표준 HTTP 서버가 `127.0.0.1`의 빈 포트에서 시작되고, HTML UI가 기본 브라우저에서 열립니다. 별도 서버 설치나 인터넷 연결은 필요하지 않습니다. 터미널은 열어 두고 사용하며, 종료할 때 Ctrl+C를 누르세요. HTML 파일만 더블클릭하면 Python 엔진에 연결되지 않으므로 반드시 위 명령으로 실행하세요.

Windows에서 `python`이 등록되지 않았다면 `py agent.py`를 사용하거나 설치된 Python 실행 파일의 전체 경로를 사용하세요. 자동으로 브라우저가 열리지 않으면 터미널의 전체 URL(`#` 뒤 연결 토큰 포함)을 복사하세요. 한 서버는 한 게임을 관리하므로 한 브라우저 탭에서 사용하세요. 새로고침하면 화면의 과거 이벤트 기록은 초기화됩니다. 기록을 보존하려면 먼저 JSON으로 저장하세요.

```powershell
# 핵심 규칙 / 알고리즘 테스트
python -m unittest tests test_web -v

# 이전 Tkinter 화면의 동작 검사 (Tcl/Tk 필요)
python gui_smoke.py

# 이전 Tkinter UI를 명시적으로 실행

# 브라우저 자동 열기 없이 지정 포트 실행

python main.py --headless --seed 42 --depth 2 --samples 32
```

## GUI 사용법

1. 최소/최대 베팅, 단위, 자동 진행 간격, A/B별 깊이와 표본 수, 시드를 설정합니다. 빈 시드는 새 정수로 생성하여 화면에 남깁니다.
2. **시뮬레이션 시작**을 누르면 첫 라운드 순서 결정까지 진행됩니다. 이후 오른쪽 키 또는 다음 단계 버튼으로 이벤트를 하나씩 관찰하세요.
3. 왼쪽 카드 테이블 위에는 딜러, 아래에는 A/B가 표시됩니다. 현재 행동하는 에이전트 테두리가 강조됩니다. 카드·합계·상태·현금·베팅을 확인하고, 아래 State 상세를 열어 이전/다음 상태를 비교하세요.
4. 오른쪽 **의사결정** 탭에서 A/B를 선택하면 그 시점까지의 마지막 평가, 평가 당시 Observation, 후보별 EU 막대, 선택 이유, 카드 확률과 탐색 통계를 볼 수 있습니다. 작은 트리는 첫 3개 카드 분기 또는 첫 4개 행동 후보만 표시하며 전체 값은 아래 상세 정보에 있습니다.
5. **이벤트 기록** 탭에서는 개별 이벤트를 클릭해 과거를 조회합니다. **결과 분석** 탭에는 정산된 라운드 기록, 승/패/무/불참 횟수와 자본·베팅·자본 차이 그래프가 나타납니다. 5라운드 뒤 최종 승자를 표시합니다.
6. **전체 의사결정 기록 저장**으로 설정과 모든 이벤트, 의사결정 근거를 JSON 파일로 내보낼 수 있습니다.

| 키 | 기능 |
|---|---|
| → | 다음 이벤트 실행; 과거 조회 중에는 이미 기록된 다음 이벤트 열람 |
| ← | 자동 진행을 멈추고 이전 기록 조회 |
| ↑ | 최신 기록으로 이동하고 자동 실행/재개 |
| ↓ | 자동 진행 일시정지 |
| Space | 자동 실행/일시정지 전환 |
| R | 초기화 후 설정 수정 가능 |

설정 창과 입력란에서는 해당 위젯의 키 조작을 우선합니다. 과거 조회는 화면의 기록 위치만 바꾸며 덱·난수열·실제 게임 상태를 되돌리지 않습니다. **현재로** 버튼으로 최신 상태로 돌아옵니다.

자동 간격은 계산 완료 이후 다음 이벤트까지의 대기 시간(ms)입니다. 계산 중에도 메인 UI 루프는 계속 동작합니다. 일시정지는 현재 진행 중인 한 이벤트 계산은 마치고 후속 이벤트를 멈춥니다. 초기화/종료는 계산 취소 신호도 전달합니다.

## 규칙과 상태 전이

- 4무늬 × 13랭크의 중복 없는 52장, A=1, J/Q/K=10입니다. 일반 카지노의 Ace=11, 블랙잭 3:2 보너스, Split, Double, 보험 규칙은 적용하지 않습니다.
- 매 라운드 새 덱을 섞어 모두가 공유합니다. 모든 배분 카드는 즉시 공개됩니다. 최초 배분은 현재 순서의 참가자들 → 딜러를 두 번 반복합니다. 참가 불가능한 플레이어는 건너뜁니다. 모두 불참이면 카드를 소비하지 않고 정산만 진행합니다.
- 첫 순서는 시드 기반 무작위, 이후에는 자본이 큰 플레이어 우선, 동률은 직전 순서의 역순입니다.
- 시작 자본은 각 1,000칩. 베팅 후보는 `하한 + k × 단위`이며 상한과 현재 현금 이하인 후보만 허용합니다. 기본은 50/100/150/200입니다. 자본이 하한 미만이면 불참하고 자본은 유지됩니다. 하한을 1,000보다 크게 설정하면 두 플레이어 모두 5라운드 내내 불참할 수 있습니다.
- 베팅 시 현금에서 한 번 차감합니다. 정산 시 승리=2×베팅, 무승부=1×베팅, 패배=0을 한 번 반환합니다. 현금과 미정산 베팅은 별도 필드로 표시합니다.
- Hit 후 합계가 21을 넘으면 즉시 Bust, 21이면 자동 Stand. Stand/Bust 상태에서 추가 Hit은 거부됩니다. 딜러는 17 미만 Hit, 그 이상 Stand입니다.
- 두 플레이어는 각자 딜러와 정산합니다. 최종 목표는 5라운드 후 상대보다 큰 자본입니다. 별도 자본 상한은 없습니다.

엔진은 generator로 `ORDER → 평가 → 선택 → BET → 개별 DEAL → 첫 플레이어 TURN_START → (평가 → 선택 → HIT 반복 / STAND) → TURN_END → 다음 플레이어 TURN_START → … → TURN_END → 딜러 → RESULT → SETTLE → FINAL` 이벤트를 전달합니다. 오른쪽 키 한 번에 전체 라운드가 실행되지 않습니다. 카드 추첨과 그 결과의 상태 변경은 하나의 원자적 Transition으로 묶습니다. 딜러 턴 직전에는 모든 참가 플레이어가 Stand/Bust인지 검증합니다.

공개 Observation에는 라운드/단계/행동자/순서, 카드와 합계, 자본, 베팅, 상태, 공개 카드 기록, 남은 카드 수, 라운드/게임 종료 여부, Reward와 정산 기록이 포함됩니다. 엔진의 `_deck`과 RNG 상태는 포함되지 않으며 깊은 복사로 전달합니다. 에이전트에는 엔진 객체를 전달하지 않습니다.

## Expectimax 알고리즘

### 1. 최종 효용

```text
U = 1    최종 내 자본 > 상대 자본
U = 0.5  최종 내 자본 = 상대 자본
U = 0    최종 내 자본 < 상대 자본
```

라운드 Reward는 실제 칩의 순변화입니다. 탐색의 평가 대상 U는 위의 최종 상대 순위이며, 현재 점수나 기대 자본으로 대체하지 않습니다. 따라서 EU는 엄밀히 `최종 승리 확률 + 0.5 × 최종 무승부 확률`의 근사치입니다.

### 2. 카드 선택 MAX / Chance

`max_node`는 Stand와 Hit의 기대 효용을 비교합니다. Hit의 `chance_node`는 남은 값별 카드 수로 모든 가능한 다음 카드 값을 열거합니다.

```text
P(v | 공개 기록) = 남은 값 v 카드 수 / 남은 전체 카드 수
EU(Hit) = Σv P(v) × V(합계 + v, 해당 카드를 제거한 남은 카드)
V = max(EU(Stand), EU(Hit))
```

초기 개수는 1~9 각각 4장, 10점 카드 16장입니다. 공개 카드가 나올 때 해당 개수를 뺍니다. 한 번 뽑은 카드는 해당 분기의 남은 카드에서도 제거하므로 **비복원 추출**입니다. 점수 규칙에서 무늬와 그림 카드 종류는 효용에 영향을 주지 않아 같은 값의 분기를 합쳤습니다.

깊이는 현재 Hit 이후의 연속 자기 의사결정 탐색을 제한합니다. 예를 들어 깊이 2이면 현재 MAX의 Hit 이후에도 한 단계 MAX를 명시적으로 확장합니다. Stand는 즉시 남은 턴의 rollout으로 넘어갑니다. Bust/21 또는 깊이 한계에 도달하면 말단 평가를 수행합니다.

### 3. 베팅 MAX와 말단 rollout

베팅 단계는 유효한 모든 금액을 MAX 후보로 평가합니다. 각 금액별로 미정 베팅·최초 배분·플레이·정산과 남은 라운드를 시뮬레이션하고 최종 U의 표본 평균을 계산합니다. 베팅 후 모든 카드를 열거하지 않으므로 베팅의 Chance 결과는 Monte Carlo로 표본화합니다.

카드 탐색 말단도 현재 공개 상태와 남은 값별 카드로 가상의 덱을 새로 섞어 현재 라운드부터 5라운드까지 진행합니다. 실제 게임의 미래 덱은 사용하지 않습니다. 같은 후보 평가에서 동일한 난수 시작점을 사용하여 후보 간 비교 분산을 줄입니다. 엔진과 A/B 탐색의 난수 생성기는 각각 분리되어 있습니다.

### 4. 근사와 모델 가정

**이 구현은 5라운드 전체에 대한 정확한 최적 정책 또는 정확한 승률을 계산하지 않습니다.**

- 명시적으로 탐색한 현재 자기 MAX 이외에서, 상대 플레이어와 자기 미래 행동은 `17 미만 Hit / 그 이상 Stand` 정책으로 예측합니다.
- 아직 정해지지 않은 상대 베팅과 미래 라운드 베팅은 최소 유효 금액을 사용합니다. 이미 공개된 베팅/Stand/Bust는 유지합니다.
- 두 플레이어의 결과는 한 가상 공용 덱 및 같은 딜러로 함께 계산하므로 상관관계를 유지합니다. 상대 정책은 결정적 모델이고, 그 정책의 카드 결과가 확률적입니다.
- 실제 A/B는 매번 Expectimax로 다시 결정합니다. 따라서 rollout의 예측 정책과 실제 미래 정책은 다를 수 있습니다.
- 표본 수가 적으면 오차와 MAX 선택 편향이 있습니다. 표본을 늘려도 정책 모델 오차 자체가 없어지지는 않습니다. UI의 EU를 실제 정확한 승률로 해석하지 마세요.
- 동률이면 먼저 열거된 행동(Stand, 또는 작은 베팅)을 선택합니다.

깊이 1~3, 말단당 표본 수 1~512를 A/B별로 설정할 수 있습니다. 깊이에 따라 카드 분기가 대략 10배씩 늘 수 있습니다. 표시되는 총 rollout 수는 모든 말단의 실제 표본 실행 횟수이고, 노드 수는 루트 평가·MAX·Chance·말단 평가 방문 수이며 rollout 안의 개별 카드 추첨은 포함하지 않습니다.

평가 기준은 [expectimax.py](expectimax.py)의 `utility`, 정책 모델은 `rollout`/`finish_round`, A/B 설정은 [agents.py](agents.py)에서 수정할 수 있습니다. 기본 깊이 2·32표본으로 먼저 관찰하고 필요할 때 늘리세요.

## 검증 범위
